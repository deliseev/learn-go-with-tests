# Установка Go, настройка среды для продуктивной работы

Официальные инструкции по установке Go доступны [здесь](https://golang.org/doc/install).

## Среда Go

### Модули Go

В Go 1.11 были представлены [Модули](https://go.dev/wiki/Modules). Этот подход является режимом сборки по умолчанию начиная с Go 1.16, поэтому использование `GOPATH` не рекомендуется.

Модули призваны решить проблемы, связанные с управлением зависимостями, выбором версий и воспроизводимыми сборками; они также позволяют пользователям запускать код Go вне `GOPATH`.

**Немного контекста: что было до модулей.** До Go 1.11 инструментарий Go полагался на соглашение под названием `GOPATH` — переменную окружения, указывающую на один каталог на вашей машине (обычно `~/go`), где должен был находиться весь код Go. Каждый проект, каждая зависимость и каждый скомпилированный пакет хранились в этом каталоге. Это означало, что вы не могли просто создать папку где угодно на вашем компьютере и начать писать код Go; компилятор не знал бы, как разрешать импорты за пределами `GOPATH`.

**Как модули решают каждую из этих проблем.** Для управления зависимостями файл `go.mod` внутри вашего проекта явно объявляет, какие внешние пакеты нужны вашему коду и в каких версиях, подобно `package.json` в Node.js. Для выбора версий Go использует детерминированный алгоритм под названием Minimum Version Selection (MVS): когда несколько зависимостей требуют разные версии одного и того же пакета, Go всегда выбирает минимальную версию, которая удовлетворяет всем, что делает результат предсказуемым. Для воспроизводимых сборок Go генерирует файл `go.sum` рядом с `go.mod`, который содержит криптографический хеш каждой зависимости. Любой, кто собирает проект, загрузит абсолютно те же файлы, проверенные по этим хешам. Если что-то изменится на удаленном сервере, сборка немедленно завершится ошибкой.

**Почему модули позволяют размещать код вне `GOPATH`.** Когда Go находит файл `go.mod` в каталоге, этот файл служит якорем проекта. Инструментарий использует его для разрешения всех импортов относительно этого модуля, без необходимости в глобальной ссылке `GOPATH`. Это означает, что вы можете создать папку проекта где угодно на вашей машине, и компилятор будет ее понимать.

Использование модулей довольно просто. Выберите любой каталог вне `GOPATH` в качестве корня вашего проекта и создайте новый модуль с помощью команды `go mod init`.

Будет сгенерирован файл `go.mod`, содержащий путь модуля, версию Go и его требования к зависимостям, которые представляют собой другие модули, необходимые для успешной сборки.

Если `<modulepath>` не указан, `go mod init` попытается угадать путь модуля из структуры каталогов. Его также можно переопределить, предоставив аргумент.

```sh
mkdir my-project
cd my-project
go mod init <modulepath>
```

Файл `go.mod` может выглядеть так:

```
module cmd

go 1.24

```

Версия Go, объявленная здесь, не просто информационная: инструментарий использует ее для определения того, какая семантика языка применяется, даже если у вас установлена более новая версия Go. Например, Go 1.22 изменил работу переменных цикла `for`, поэтому коду, который опирается на это поведение (как мы делаем позже в главе о [параллелизме](concurrency.md)), необходим `go.mod`, объявляющий версию `1.22` или более позднюю, чтобы вести себя ожидаемым образом. Поддержание этой версии в разумно актуальном состоянии избавит вас от некоторой путаницы при отладке в дальнейшем.

Встроенная документация предоставляет обзор всех доступных команд `go mod`.

```sh
go help mod
go help mod init
```

## Линтинг Go

Улучшенная версия линтера по умолчанию может быть настроена с использованием [GolangCI-Lint](https://golangci-lint.run).

Его можно установить следующим образом:

```sh
brew install golangci-lint
```

## Рефакторинг и ваши инструменты

Большое внимание в этой книге уделяется важности рефакторинга.

Ваши инструменты могут помочь вам выполнять более масштабный рефакторинг с уверенностью.

Вы должны быть достаточно хорошо знакомы со своим редактором, чтобы выполнять следующие действия с помощью простой комбинации клавиш:

-   **Извлечение/встраивание переменной**. Извлечение магических значений и присвоение им имени позволяет быстро упростить ваш код.
-   **Извлечение метода/функции**. Жизненно важно уметь брать часть кода и извлекать из нее функции/методы.
-   **Переименование**. Вы должны уметь уверенно переименовывать символы во всех файлах.
-   **go fmt**. В Go есть стандартизированный форматер под названием `go fmt`. Ваш редактор должен запускать его при каждом сохранении файла.
-   **Запуск тестов**. Вы должны уметь выполнять любое из вышеперечисленного, а затем быстро перезапускать свои тесты, чтобы убедиться, что ваш рефакторинг ничего не сломал.

Кроме того, чтобы помочь вам работать с вашим кодом, вы должны уметь:

-   **Просмотр сигнатуры функции**. Вы никогда не должны сомневаться в том, как вызывать функцию в Go. Ваша IDE должна описывать функцию с точки зрения ее документации, ее параметров и того, что она возвращает.
-   **Просмотр определения функции**. Если все еще неясно, что делает функция, вы должны иметь возможность перейти к исходному коду и попытаться разобраться самостоятельно.
-   **Поиск использования символа**. Понимание контекста функции может помочь вам принимать решения при рефакторинге.

Освоение ваших инструментов поможет вам сосредоточиться на коде и уменьшить переключение контекста.
