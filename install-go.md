# Установка Go, настройка среды для продуктивной работы

Официальные инструкции по установке Go доступны [здесь](https://golang.org/doc/install).

## Среда Go

### Go модули

Go 1.11 представил [модули](https://go.dev/wiki/Modules). Этот подход является режимом сборки по умолчанию с Go 1.16, поэтому использование `GOPATH` не рекомендуется.

Модули призваны решать проблемы, связанные с управлением зависимостями, выбором версий и воспроизводимыми сборками; они также позволяют пользователям запускать Go код вне `GOPATH`.

**Немного контекста: что было до модулей.** До Go 1.11, цепочка инструментов Go полагалась на соглашение под названием `GOPATH`, переменную среды, указывающую на один каталог на вашей машине (обычно `~/go`), где должен был храниться весь Go код. Каждый проект, каждая зависимость и каждый скомпилированный пакет хранились в этом каталоге. Это означало, что вы не могли просто создать папку где угодно на вашем компьютере и начать писать Go код; компилятор не знал бы, как разрешать импорты вне `GOPATH`.

**Как модули решают каждую из этих проблем.** Для управления зависимостями, файл `go.mod` внутри вашего проекта явно объявляет, какие внешние пакеты нужны вашему коду и в каких версиях, аналогично `package.json` в Node.js. Для выбора версий Go использует детерминированный алгоритм под названием Minimum Version Selection (MVS): когда несколько зависимостей требуют разных версий одного и того же пакета, Go всегда выбирает минимальную версию, которая удовлетворяет всем, делая результат предсказуемым. Для воспроизводимых сборок Go генерирует файл `go.sum` рядом с `go.mod`, который содержит криптографический хеш каждой зависимости. Любой, кто собирает проект, загрузит абсолютно те же файлы, проверенные по этим хешам. Если что-либо изменится на удаленном сервере, сборка немедленно завершится ошибкой.

**Почему модули позволяют коду находиться вне `GOPATH`.** Когда Go находит файл `go.mod` в каталоге, этот файл действует как якорь проекта. Цепочка инструментов использует его для разрешения всех импортов относительно этого модуля, без необходимости в глобальной ссылке `GOPATH`. Это означает, что вы можете создать папку проекта где угодно на вашей машине, и компилятор будет ее понимать.

Использование модулей довольно просто. Выберите любой каталог вне `GOPATH` в качестве корня вашего проекта и создайте новый модуль с помощью команды `go mod init`.

Будет сгенерирован файл `go.mod`, содержащий путь модуля, версию Go и его требования к зависимостям, которые являются другими модулями, необходимыми для успешной сборки.

Если `<modulepath>` не указан, `go mod init` попытается угадать путь модуля из структуры каталогов. Его также можно переопределить, предоставив аргумент.

```sh
mkdir my-project
cd my-project
go mod init <modulepath>
```

Файл `go.mod` может выглядеть так:

```
module cmd

go 1.24

```

Объявленная здесь версия Go не просто информативна: цепочка инструментов использует ее для определения того, какая семантика языка применяется, даже если у вас установлена более новая версия Go. Например, Go 1.22 изменил работу переменных `for` циклов, поэтому код, полагающийся на это поведение (как мы это делаем позже в главе [concurrency](concurrency.md)), требует `go.mod`, объявляющего `1.22` или более позднюю версию, чтобы работать ожидаемым образом. Поддержание этой версии в разумно актуальном состоянии избавит вас от некоторой запутанной отладки в дальнейшем.

Встроенная документация предоставляет обзор всех доступных команд `go mod`.

```sh
go help mod
go help mod init
```

## Go линтинг

Улучшение по сравнению с линтером по умолчанию может быть настроено с помощью [GolangCI-Lint](https://golangci-lint.run).

Его можно установить следующим образом:

```sh
brew install golangci-lint
```

## Рефакторинг и ваши инструменты

Большое внимание в этой книге уделяется важности рефакторинга.

Ваши инструменты могут помочь вам выполнять более масштабный рефакторинг с уверенностью.

Вы должны быть достаточно знакомы со своим редактором, чтобы выполнять следующее с помощью простой комбинации клавиш:

- **Извлечение/встраивание переменной**. Извлечение "магических" значений и присвоение им имен позволяет быстро упростить ваш код.
- **Извлечение метода/функции**. Жизненно важно уметь брать часть кода и извлекать из нее функции/методы.
- **Переименование**. Вы должны быть уверены в возможности переименовывать символы между файлами.
- **go fmt**. Go имеет предписывающий форматер под названием `go fmt`. Ваш редактор должен запускать его при каждом сохранении файла.
- **Запуск тестов**. Вы должны быть в состоянии выполнить любое из вышеперечисленного, а затем быстро перезапустить свои тесты, чтобы убедиться, что ваш рефакторинг ничего не сломал.

Кроме того, чтобы помочь вам работать с вашим кодом, вы должны уметь:

- **Просмотр сигнатуры функции**. Вы никогда не должны сомневаться в том, как вызвать функцию в Go. Ваша IDE должна описывать функцию с точки зрения ее документации, ее параметров и того, что она возвращает.
- **Просмотр определения функции**. Если по-прежнему неясно, что делает функция, вы должны иметь возможность перейти к исходному коду и попытаться разобраться самостоятельно.
- **Поиск использований символа**. Понимание контекста функции может помочь вам принимать решения при рефакторинге.

Освоение ваших инструментов поможет вам сосредоточиться на коде и уменьшить переключение контекста.
